# Доступы

OWNER — единственная строка `system_owner(singleton=true)`, с UNIQUE user_id, PRIMARY KEY singleton и CHECK(singleton). Создаётся только CLI, защищённым блокировкой таблицы. API изменения владельца нет. Должности не используются для авторизации.

Все permissions читаются из БД на запросе. Отзыв действует на следующем запросе. OWNER проходит все проверки, **но не обходит геопроверку**, окна регистрации, QR и принадлежность ожидаемым участникам для собственной отметки.

| Право              | Разрешённые действия                                        | Область                                  |
| ------------------ | ----------------------------------------------------------- | ---------------------------------------- |
| users.manage       | приглашения, блокировка, новая активация; не OWNER          | TEAM или отдел целевого участника        |
| departments.manage | создание (TEAM), состав, название, архив                    | TEAM / DEPARTMENT                        |
| meetings.create    | создание собрания и снимка ожидаемых участников             | TEAM / DEPARTMENT                        |
| meetings.manage    | название/точка до первой отметки, переходы жизненного цикла | TEAM / DEPARTMENT / MEETING              |
| meetings.qr.show   | получение QR, не просмотр чужих отметок/отзывов             | TEAM / DEPARTMENT / MEETING              |
| attendance.read    | чужая посещаемость в отчётах                                | TEAM / исторический DEPARTMENT / MEETING |
| tasks.create       | создание задач                                              | TEAM / DEPARTMENT                        |
| tasks.manage       | изменение срока, ответственного, названия и описания        | TEAM / DEPARTMENT                        |
| tasks.review       | принятие и возврат с комментарием                           | TEAM / DEPARTMENT                        |
| feedback.read      | текст, режим, имя только у именного отзыва, заметки         | TEAM / отдел собрания / MEETING          |
| feedback.manage    | статус и внутренние заметки, не авторский текст             | TEAM / отдел собрания / MEETING          |
| reports.export     | CSV; дополнительно нужны права чтения каждого объекта       | TEAM / DEPARTMENT / MEETING              |

Создание не подразумевает дальнейшее управление: для самостоятельного ведения встреч делегируйте create + manage + qr.show. Для обработки отзывов: read + manage. Некорректно применённые области (например tasks.create для MEETING) не дают доступа к задачам.

Базовый участник:

- видит приглашённые собрания и только свою посещаемость/показатели;
- может отмечаться, только будучи ожидаемым участником;
- читает личные задачи, задачи с соисполнением и задачи своего активного отдела;
- меняет рабочий статус и отправляет результат только если ответственный/соисполнитель;
- не принимает результат без tasks.review;
- оставляет отзыв после CLOSED, если был в ожидаемом списке;
- не читает отправленные отзывы без отдельного права (для анонимных не существует «мои отзывы»).

Отделы исторических встреч не пересчитываются при переводе. Для командной встречи сохраняется последний активный отдел участника на момент приглашения; для встречи отдела — её отдел. При нескольких членствах это инженерное правило разработки, его нужно согласовать до запуска.

users.manage — чувствительное право: разрешает выдавать новые ссылки установки пароля обычным аккаунтам в своей области. Не выдавайте его людям, которым не доверяете управление доступом участников этой области. Любое изменение отражено в аудите. Единственный OWNER исключён из этих операций.

## Узкое исключение для OWNER: забытый уход

По подтверждению владельца от 17 ноября 2026, POST meetings/:id/manual-checkout доступен строго requireOwner, не grants. Даже meetings.manage/attendance.read TEAM не дают это действие. Требуются существующий приход, отсутствие ухода, статус OPEN/CLOSED, фактическое время не в будущем и не до прихода, причина. Источник OWNER_MANUAL, автор/время внесения и аудит обязательны. Отсутствует ручной приход, изменение существующего ухода, обход заблокированного аккаунта и скрытая имитация GPS.
