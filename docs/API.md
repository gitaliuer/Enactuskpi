# API v1

Все ответы JSON, кроме CSV. `Cache-Control: no-store, private`. Cookie `enactus_session`: HttpOnly, SameSite=Lax, Secure при HTTPS APP_ORIGIN. В production APP_ORIGIN обязан быть HTTPS. Мутации требуют `Origin` равный APP_ORIGIN и `Content-Type: application/json`. Максимум тела 64 KiB. Все схемы strict (неизвестные поля отвергаются). UUID проверяются. Даты ISO 8601 с offset, серверные отметки — UTC.

Ошибки: `{error: CODE, details?: {distance, radius}}`, валидация дополнительно `fields: [{path,message}]`. 401 UNAUTHENTICATED/INVALID_CREDENTIALS, 403 FORBIDDEN, 404 NOT_FOUND (включая закрытый чужой объект), 409 CONFLICT, 429 RATE_LIMITED, 400 бизнес-ошибки, 500 SERVER_ERROR без внутренностей.

С 17 ноября 2026 по указанию владельца действует упрощённое расписание: приход разрешён с starts_at−10 минут, только в OPEN, до ручного закрытия/отмены организатором; ends_at — плановое окончание, не запрет прихода/ухода. Опоздание строго позже starts_at+15 минут (ровно +15:00 не опоздание), включая пересчёт существующих отчётов/CSV. Уход без дедлайна и без QR, после собственного прихода, с обычной геопроверкой, в OPEN или CLOSED. CANCELLED блокирует новые отметки; автоматического ухода, перезаписи времени и повторного входа нет.

Старые поля registration_open_at/registration_close_at/checkout_close_at/late_after_minutes принимаются при POST только для совместимости старых клиентов, но значения игнорируются: сервер сам задаёт start−10 минут, NULL, NULL, 15. Для существующих собраний старые значения хранятся без изменения, но не задают сроки отметок. Миграция 004 разрешает NULL для устаревших closing columns, без удаления записей и изменения времён attendance.

QR: HMAC-SHA256, base64url JSON с meetingId, purpose=check-in, interval=floor(serverMs/180000), expiresAt=(interval+1)*180000, version. Один токен интервала для всех экранов, много участников. Проверка в момент POST, **без grace period**. Секрет не выходит в браузер. Закрытие и отмена проверяются в той же транзакции, что отметка; строка собрания FOR UPDATE сериализует гонки. Время PostgreSQL now(). Уникальность meeting+user. Повтор уже выполненного действия возвращает существующую собственную запись даже после истечения QR: это восстановление результата, не новая отметка и не перезапись времени.

Ошибки отметок: MEETING_CLOSED, QR_EXPIRED, QR_INVALID, GEO_UNAVAILABLE, GEO_STALE, GEO_INACCURATE, GEO_OUTSIDE_RADIUS, CHECK_IN_REQUIRED. Идемпотентные повторы возвращают repeated=true вместо ошибки ALREADY_CHECKED_IN/OUT. Клиентские запрет GPS и timeout не отправляют POST отметки и показывают GEO_PERMISSION_DENIED/GEO_TIMEOUT. Ручного attendance PATCH/POST API нет.

Ссылки только http/https. React экранирует текст; пользовательский HTML не рендерится. original_due_at сохраняется; accepted_due_at фиксируется при принятии; все сдвиги срока видны в events. Метрика «в срок» сравнивает принятое время с accepted_due_at, не скрывая историю пересогласования.

| Метод и путь               | Вход                                                                                            | Правила / результат                                                                                                                                         |
| -------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST meetings/:id/feedback | mode ANONYMOUS/NAMED, comment, positive?, improvement?, rating? 1..5/null, idempotency_key UUID | ожидаемый участник, CLOSED; 201 `{ok:true}`. Ключ повторять при неизвестном сетевом результате                                                              |
| GET feedback               | —                                                                                               | до 500 по feedback.read; coarse_date, имя только NAMED, внутренние notes                                                                                    |
| PATCH feedback/:id/status  | status NEW/VIEWED/PROCESSED, note?                                                              | feedback.manage; авторский текст менять нельзя                                                                                                              |
| GET reports                | from?, to?, department?, user?, meeting?, format? csv                                           | собственные строки, чужие по attendance.read; фильтры после ограничения прав; summary с показателями доступных участников; kind=metrics для CSV показателей |

Экспорт дополнительно требует reports.export для каждой строки. UTF-8 BOM, RFC-подобное quoting, защита от spreadsheet formula injection. В MVP экспорт отчёта посещаемости. Анонимный отзыв не содержит точного времени и не связан с автором в dedup/audit. Против случайных повторов — случайный ключ 1 ч без user_id, плюс отдельный счётчик частоты пользователя без ID отзыва и текста. Уникальность «один анонимный отзыв на человека» намеренно не обещается.

Списки ограничены 500, audit — 200. Это предел первой версии, не заявленная нагрузочная ёмкость; отчёт посещаемости без этого среза. Для команды выше этих размеров до запуска нужны pagination и нагрузочное испытание. Не выводите чувствительные тела HTTP или URL с QR/activation в аналитику/proxy-логи. QR использует fragment URL (не отправляется в HTTP access log), краткоживущий bearer token; front удаляет его из history при загрузке, Referrer-Policy no-referrer.
