# Enactus Zhetysu · Team Hub

Закрытая рабочая платформа: индивидуальные аккаунты, единственный OWNER, делегируемые scoped-права, собрания, динамический QR, автоматическая геопроверка прихода/ухода, задачи с приёмкой, именные/анонимные отзывы, история и CSV.

**Это работающая первая реализация, не разрешение на промышленный запуск.** Внешняя PostgreSQL, реальный GPS, мобильные устройства, восстановление backup и условия хостинга должны быть проверены отдельно. Сервис не опубликован на Vercel. Встроенного пароля и публичной регистрации нет. Никакие платные услуги не подключены.

## Стек и структура

Node.js 22+, Next.js 16 / React 19 / TypeScript, Zod, PostgreSQL через `pg`, Argon2id (`@node-rs/argon2`), QRCode, Vitest и Playwright. Точные версии в `package-lock.json`; установка `npm ci`. Версии проверены по npm registry 17.11.2026. Выбран параметризованный SQL вместо ORM: правила находятся в серверных модулях, воспроизводимая схема — в SQL-миграциях.

```
src/app/                  мобильный React UI и серверный API
src/app/api/[...path]/     единый HTTP dispatcher, origin/CSRF, схемы и ошибки
src/server/auth.ts        хеши паролей, cookie sessions, активация
src/server/core.ts        права, QR, геодезия, аудит, CSV, rate limiting
src/server/management.ts  участники, отделы, выдача/отзыв прав
src/server/meetings.ts    жизненный цикл, снимок приглашённых, отметки
src/server/tasks.ts       задачи, обсуждение, приёмка, события
src/server/feedback.ts    анонимность и обработка отзывов
src/server/reports.ts     история, личные/областные показатели
src/server/db.ts          PostgreSQL pool / только dev: PGlite
src/lib/i18n.ts           русский словарь, подготовлен для перевода
migrations/               версионированный SQL, журнал schema_migrations
scripts/                  миграции, OWNER, восстановление, тестовые данные
```

## Быстрый локальный запуск без внешних аккаунтов

PGlite — локальный PostgreSQL WASM, **не имитация сохранения**: `.local/db` содержит реальную реляционную БД с constraints и транзакциями. Это удобный режим разработки одного процесса, не внешний production PostgreSQL и не решение для Vercel. Не запускайте одновременно два процесса на одной PGlite-директории.

```bash
npm ci
cp .env.example .env
# В .env:
# LOCAL_DATABASE=1
# APP_ORIGIN=http://localhost:3000
# QR_SECRET=<локально сгенерированный случайный секрет не короче 32 символов>
# DATABASE_URL в этом режиме не используется.
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
npm run db:migrate
npm run owner:create -- ali
npm run dev
```

CLI выводит **приватную одноразовую ссылку** на установку пароля владельца (1 час). Откройте её на адресе APP_ORIGIN, задайте пароль минимум 12 символов, затем войдите с логином `ali`. CLI не задаёт и не публикует пароль. Не отправляйте ссылку в общий чат, не коммитьте и не сохраняйте её в CI-логах. Команда создания второго владельца откажет.

Для preview Arena используйте фактический HTTPS-адрес preview в APP_ORIGIN. Сервер слушает `0.0.0.0`; браузерные вызовы только относительные `/api/...`. Не заменяйте Origin доверенным значением из входящего Host. На телефоне обычный HTTP по локальной сети не подходит для Geolocation — нужен доверенный HTTPS.

Необязательные **вымышленные** отделы и приглашённые аккаунты без паролей:

```bash
SEED_TEST_DATA=yes npm run db:seed
```

Seed не создаёт успешные отметки и не подменяет статистику. Участников нужно активировать обычными ссылками из панели владельца.

## Обычная PostgreSQL

Создайте пустую тестовую БД и отдельную учётную запись с правами миграции. В `.env`: `LOCAL_DATABASE=0`, `DATABASE_URL=...`, `APP_ORIGIN=...`, `QR_SECRET=...`. Выполните `npm run db:migrate`, затем `npm run owner:create -- ali`.

Миграции применяются транзакционно, с advisory lock и журналом. Не запускаются скрыто при HTTP-запросах или при `next build`. Для production желателен отдельный migration user; runtime user не должен иметь DDL и доступ к управлению OWNER вне приложения. Для Vercel задайте одобренный pooled URL PostgreSQL с проверяемым TLS (параметры по документации выбранного провайдера). Не используйте `rejectUnauthorized:false`. Драйвер `pg`, pool max=5 на экземпляр, `attachDatabasePool` из `@vercel/functions`. Реальную суммарную нагрузку на пул требуется измерить.

## Работа владельца

1. **Отделы** → создать отдел.
2. **Участники** → пригласить, указать имя, уникальный логин и отдел; скопировать одноразовую ссылку (24 часа) и передать лично согласованным каналом. Пароль участник задаёт сам.
3. **Доступы** → выдать конкретное право в области TEAM / DEPARTMENT / MEETING. Для ведения собраний нужны create, manage и qr.show; для отзывов read и manage. Только OWNER выдаёт и отзывает права. [Матрица прав](docs/PERMISSIONS.md).
4. **Собрания** → создать черновик с координатами, окнами и конкретными ожидаемыми участниками; отметить обязательность для каждого. Все поля времени в интерфейсе — Asia/Almaty (UTC+5). Затем запланировать и открыть регистрацию.
5. На встрече **Показать QR**. Чёрно-белый код с quiet zone, таймер, проверка соединения. Код действует до границы текущего 180-секундного интервала (при первом открытии остаток может быть меньше трёх минут).
6. Участник сканирует обычной камерой, входит, нажимает **Я пришёл** и разрешает геолокацию. GET не создаёт посещение. Для ухода — **Я ухожу**, новая геопроверка, без повторного QR (предлагаемое решение MVP).
7. Закрытие/отмена сразу блокируют новые отметки на сервере. На открытом экране QR дополнительно проверяется соединение/доступ каждые 15 с, при смене интервала и возвращении вкладки. Постоянного сервера и cron для QR нет.
8. **Задачи** → ответственный, соисполнители, отдел, результат, срок, приоритет. Исполнитель отправляет работу на проверку; проверяющий принимает либо возвращает с комментарием. Сдвиги срока/ответственного остаются в истории.
9. После CLOSED ожидаемый участник может оставить **отзыв** без повторного ввода имени. Именной использует имя аккаунта; анонимный не имеет связи с автором. Обработчики меняют статус и внутренние заметки, не авторский текст.
10. **Отчёты** → период, отдел, участник, собрание, CSV посещаемости или показателей. Для чужих данных нужны права чтения; для каждого экспортируемого объекта — дополнительно reports.export. Нулевой знаменатель — «Нет данных».

### Геопроверка и решения разработки

- Радиус **200 м включительно**, Haversine на сервере; accuracy не прибавляется к радиусу и не вычитается из него. Численная погрешность сравнения 0.0000001 м — только для floating point на точной границе.
- `GEO_MAX_ACCURACY=100` м, `GEO_MAX_AGE_SECONDS=30` с — **предлагаемые пороги, не согласованные правила команды**. Неверная конфигурация не отключает проверку. Есть проверка времени измерения и challenge на 60 с, привязанный к пользователю/собранию/действию.
- Браузер запрашивает high accuracy, maximumAge=0, timeout=15 с, максимум одна повторная попытка; есть отмена и конкретные ошибки. Нет фонового GPS и IP-замены. Исключение по отдельному решению владельца: только OWNER может внести забытый уход после уже отмеченного прихода, с причиной и явной пометкой «вручную, без GPS».
- Координаты участника не сохраняются. В attendance — расстояние, точность, серверное время. Клиент может подделать GPS: эта система **не даёт криптографического доказательства присутствия**.
- Координаты встречи неизменяемы после первой отметки. Исправление ошибки: отмена и новое собрание, не редактирование истории.
- Одна пара вход/выход. Повторный вход, перезапись уже записанного ухода и автоматический уход отсутствуют. Только OWNER может заполнить отсутствующий уход фактическим временем со слов участника; автор, время внесения и причина сохраняются в attendance/audit и экспортируются. Закрытие не создаёт уход. «Время между отметками» не означает непрерывное присутствие.
- Пропуск: только CLOSED + required + нет принятого входа; CANCELLED исключён. Уважительные причины/штрафы не придуманы и не включены; порог опоздания nullable на каждом собрании.
- Допуск к отзыву: ожидаемый участник, независимо от геоотметки, после CLOSED. Это предложенное правило, подтвердить до реального запуска.
- Даты хранятся timestamptz UTC, показываются Asia/Almaty. Язык русский; строки в словаре, казахского перевода пока нет.

## Восстановление доступа

Обычный аккаунт: OWNER/пользователь с users.manage выдаёт новую одноразовую ссылку. Старые сессии и неиспользованные ссылки отзываются. Блокировка не удаляет историю. Для активации заблокированный аккаунт сначала нужно разблокировать.

Восстановление единственного OWNER — только оператор с уже имеющимся доступом к серверу/БД:

```bash
npm run owner:recover -- --confirm
```

Команда не создаёт второго владельца, отзывает его сессии/ссылки и выводит приватную ссылку (1 час). Безопасность операционного доступа/доставки ссылки нужно определить до запуска. Внешняя почта/мессенджер не подключены.

## Проверки

```bash
npm run lint
npm run typecheck
npm test                    # unit + integration на чистом in-memory PGlite
npm run build
npm run test:e2e:setup      # исключительно .local/e2e, вымышленные пользователи
npm run test:e2e            # отдельный dev server :3100, Chromium
```

E2E setup разрушает **только специально обозначенную тестовую БД**, пишет случайные пароли в игнорируемый файл `.local/e2e-credentials.json`, не печатает их. Playwright использует Chromium из npm (в Linux извлекает bundled NSS libraries в `.local/`). На других ОС используйте обычный установленный Playwright Chromium и адаптируйте executablePath. В браузерных тестах не отключается web security. GPS mock в E2E не заменяет реальное устройство. [Результаты и незакрытая приёмка](docs/VERIFICATION.md).

## Vercel: подготовка, не выполненное размещение

1. До реальных данных согласовать пригодность **Hobby для организационной платформы**, провайдера/регион PostgreSQL, правовые требования Казахстана, backups, хранение/удаление, нагрузку и стоимость. Некоммерческий статус не даёт автоматического разрешения на любой Hobby use case.
2. Подключить репозиторий как Next.js project (Node 22+), `npm ci`, `npm run build`. Никаких фоновых процессов или локальной БД в runtime.
3. Раздельные переменные development/preview/production: DATABASE_URL, HTTPS APP_ORIGIN, случайный QR_SECRET, GEO_MAX_ACCURACY, GEO_MAX_AGE_SECONDS. **Не задавать LOCAL_DATABASE=1 на Vercel.** Preview — отдельная БД только с тестовыми данными.
4. Из защищённой среды с нужным DATABASE_URL выполнить миграции, создать OWNER. Не выводить activation link в build logs. Не запускать owner:create при каждом деплое.
5. Проверить реальный HTTPS URL: login/logout, Secure cookie, Origin, права/IDOR, открытие и истечение QR, GPS Android/iOS, pool/connection limits, экспорт. Только после проверки объявлять запуск.
6. При обновлении: backup → тест миграции на восстановленной копии → тесты → применить совместимую миграцию → deploy → smoke tests. Не откатывайте схему удалением исторических данных. Для несовместимого изменения используйте отдельную миграцию и план восстановления.

## Backup, восстановление и обслуживание

Для одобренной внешней PostgreSQL (`pg_dump/pg_restore` соответствующей версии):

```bash
# Переменные задавать безопасно в окружении, не вставлять реальные URL в историю чата.
pg_dump --format=custom --no-owner --file=backup.dump "$DATABASE_URL"
# Восстанавливать ТОЛЬКО в новую изолированную БД, не поверх production:
pg_restore --no-owner --no-privileges --dbname="$RESTORE_DATABASE_URL" backup.dump
```

Backup содержит персональные данные и password hashes: шифрование, ограниченный доступ, отдельное хранилище, согласованный срок. Перед запуском реально восстановите backup, сравните counts/constraints, проверьте вход в тестовой среде, историю и права. На восстановленной копии отзовите все сессии и activation_tokens. **Здесь внешний backup/restore не проверен.** Для PGlite в разработке копируйте `.local/db` только после остановки процесса; это не production backup-план.

`npm run db:prune` удаляет истёкшие challenge, sessions, activation tokens, rate limits, случайные feedback dedup keys. Запускать из защищённой среды по утверждённому расписанию. Исторические встречи/задачи/отзывы он не удаляет. Политика хранения бизнес-данных пока не определена.

## Приватность и ограничения

- Анонимность не абсолютна: текст, небольшая группа и инфраструктурные логи могут раскрывать автора косвенно. В приложении нет скрытого user hash/связи, «раскрытия автора» и timestamp отправки анонимного текста. Строгая уникальность анонимного отзыва на участника не обещается.
- QR и activation токены передаются во fragment URL, который не отправляется в HTTP-запросе, удаляются из видимой истории после чтения. Session token только HttpOnly cookie, БД хранит его SHA-256. Не подключайте запись HTTP bodies/аналитику с секретами и отзывами.
- CSP и безопасный React text rendering есть; CSP допускает inline scripts/styles для Next.js. Перед production желателен отдельный security review и усиление nonce-based CSP. Не трактуйте наличие тестов как независимый аудит безопасности.
- Готовность под одновременную нагрузку не заявляется. Некоторые списки ограничены 500, аудит 200; нет серверной пагинации. До превышения этих объёмов нужно добавить pagination. Отчёт посещаемости не срезается этим пределом.
- Внешний PostgreSQL pool, реальный Vercel, GPS на устройствах, резервное восстановление и юридические условия не проверены в этой среде.
